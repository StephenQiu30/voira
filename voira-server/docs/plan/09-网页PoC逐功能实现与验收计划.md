# 09 网页PoC逐功能实现与验收计划

## 01 目标与规格基线

目标是在本机网页逐角色跑通：预览 → 核对对应AI与人物配置 → 开始 → 真实画面/声音 → 提问 → 对应AI回答 → Vidu text_tts → 人工继续 → 最近3轮上下文 → 结束核对。当前18项功能；下表包含当前18项功能，13个后置功能不排实现任务。

基线：[需求索引](../requirement/01-数字人MVP需求草案.md)、[设计索引](../design/00-功能设计索引.md)、[共享契约](../design/03-Vidu网页PoC最小业务设计.md)与[PRD](../prd/01-网页数字人PoC产品与验收标准.md)。各自维护范围、设计和验收；实施前核对当前版本。

技术栈、目录与生成协议沿用[PROJECT](../../PROJECT.md)及前后端规范。任务中的代码路径均为拟落点，不表示文件已经存在。资源/人选/可用容量未提供，不虚构负责人姓名、点数、工期或Sprint承诺；先按依赖交付，排期时再据实际容量预留15%—20%不确定性缓冲。

## 02 执行门槛与完成口径

| 门槛 | 条件及影响 |
|---|---|
| G-CODE 代码阶段 | 用户后续明确允许实现，并完成本批涉及需求/契约的评审与冲突核对。布局与素材准备服务已单独获准实现；会话业务尚未开放，不以预算未定阻塞文档工作 |
| G-CALL 真实调用 | 实际调用前确认账号/模型/地区、样本范围、时长/次数/金额、费率与预算预留、值守/人工终止方式。包括试听、资产处理和Codex隔离探测，不以免费/最小探测自动豁免 |
| T-051 实测准入出口 | 先满足G-CALL，再在批准额度内完成必要素材/音色冻结、账号能力及实际Codex受限配置核验；输出可追溯基线供真实TC使用。无权限隔离证据不开放普通输入 |
| 产品验收 | T-052—056依据真实TC与人工观察给结论；静态构建、Mock或源码阅读不替代真实声音、口型、回答与终止结果 |

未选择具体voice ID/送模图、尚未确认实际额度时，获准实现后可以用明确标记的测试配置完成T-029—050；真实模式仍应配置未就绪。真实动态效果在TC-020评审，不循环要求动态已通过才能开始验证。

**任务完成分层：** T-029—049验收本任务代码、契约和局部受控测试；T-050验收全链路模拟联调；这些完成均不将对应真实AC/TC标通过。每项功能必须最终关联T-052—056真实证据才能认定产品能力通过。失败/未执行如实记录，不用跳过用例提高通过率。

旧T-006的“预拆分任务”产物由本轮完成，但其正式实施基线确认出口仍保留；T-001—005也不被自动标已完成。后续授权时按选定批次核对基线，不要求先完成直播、所有未来候选或已后置的账号问题。

## 03 前后端实施顺序

| 批次 | 后端先交付 | 前端可衔接的工作 | 联调出口 |
|---|---|---|---|
| A 公共基础 | T-029契约，T-031账本；T-032夹具后接T-033协议适配 | T-029 schema可用后T-030建立页面/生成API；与账本工作可交错 | 可本机启动、接口生成匹配、模拟环境无外部请求 |
| B 配置与退出保护 | T-034诊断、T-035预算；T-036素材、T-037声音、T-038人设；T-039结束 | 配置预览、缺项、用量/结束状态，T-040持续错误 | 先证明未知/退出/预算保护，再尝试开始场景 |
| C 会话与媒体 | T-041创建/凭据/心跳，配置准备可先由模拟提供 | T-042媒体订阅 → T-043声音恢复；使用T-039结束清理 | 模拟首帧/播放受阻/离开清理；不冒充真实媒体 |
| D 答案准备 | T-044长度规则、T-045上下文可在基础后先做；T-046按角色绑定的AI适配 | 复用生成阶段和错误区，不增加配置后台 | 替身验证最终答案、权限配置边界和取消协议 |
| E 问答与轮次 | T-047输入 → T-048播读 → T-049人工继续/上下文提交 | 草稿、回答、忙状态与继续按钮逐步接入 | 不打断、不重复、只解锁、正确3轮窗口 |
| F 集成与真实验收 | T-050模拟全链路 → T-051实测准入 | 浏览器全路径与真实媒体观察 | T-052—056按原TC执行并核对费用/复现 |

允许前端基于T-029生成类型和T-032模拟快照先做显示，但每项完成仍要与对应后端契约联调；不手写另一套DTO。后端先以测试依赖构造会话验证结束/预算，避免“必须先真实开始才能实现退出”的循环。所有会话最终在T-050接入T-046逐角色准备检查，不能保留伪就绪开关。

一条主要串行依赖链为T-029 → T-030 → T-032 → T-033 → T-039 → T-041 → T-047 → T-048 → T-049 → T-050 → T-051 → T-052—056；T-031/034/035/036/037/038、T-042/043与T-044/045/046是汇入依赖，不可跳过。具体完整依赖以任务卡及BLACKLOG为准；这里的可交错仅指开发排程，不授权本轮启动Agent或代码。

## 05 公共基础任务

以下5项是跨功能工程依赖，不新增业务FR。共同前置为G-CODE；人员只指定职责角色，实际认领与容量待安排。

### T-029 后端应用与自动接口契约

- 来源：NFR-003/004/007；DES-012—017；支撑AC-002/003/007/019。
- 依赖：T-028；G-CODE。责任角色：后端实现者。
- 拟改动范围：backend/app/main.py、api、schemas、core及依赖配置（拟建/补齐）；保持功能路由，不加/v1。
- 步骤：锁定兼容Python/FastAPI/Pydantic与检查工具 → 定义8个HTTP端点的请求/响应/错误模型及稳定operation_id → 装配同源/Host/令牌检查和依赖注入 → 自动提供/openapi.json与/docs。未接入的写用例明确不可用，禁止返回伪成功。
- 验收：打开页面/接口文档不创建会话；schema覆盖可空、枚举、422/403/409/429与no-store边界；缺配置时只读可查、写操作不可用。记录锁定版本与实际启动方法，读取schema零外调。
- 证据：锁定版本、实际检查输出及受控测试结果，记录本任务ID；当前未执行，不标真实TC通过。
- 风险与回退：保留原骨架与资产，启动失败修复配置；不采用直接跑第三方reference的方式恢复。

### T-030 前端应用与生成HTTP客户端

- 依赖：T-029；G-CODE。责任角色：前端实现者。
- 拟改动范围：frontend/src/app、components/ui、lib、api、features、stores及构建配置（拟建/补齐）。
- 步骤：锁定Next.js/React/TypeScript及Radix版shadcn/Tailwind等 → 复用当前DESIGN建立PoC页面壳 → 从T-029自动schema生成src/api → 映射Axios params/data/headers/AbortSignal/返回值与错误。使用现成CLI，不建自定义脚本。
- 验收：typecheck/lint/format:check/build及必要请求适配检查通过；生成客户端可处理可空与错误、取消不自动重发；浏览器/SSR无长期密钥。复用七位角色展示，按各自绑定与准备状态开放当前会话入口；不把静态素材齐全直接视为实时就绪。
- 证据：锁定版本、实际检查输出及受控测试结果，记录本任务ID；当前未执行，不标真实TC通过。
- 风险与回退：锁定版本不兼容则调整兼容组合与生成配置，禁止手改生成DTO或改schema版本号掩盖问题。

## 06 按功能实施任务卡

每项保留任务ID、配置版本、模拟模式、输入／状态／调用计数和检查结论，原始证据放output。

每张卡按职责关联FR，七项AI适配共用T-046；“后端→前端→联调”是本功能交付顺序。前端可先做模拟显示，最终必须完成联调；无独立前端功能的条目明确复用现有页面，不人为扩围。共同前置G-CODE，各任务验收在T-032受控依赖下完成；执行状态仅在BLACKLOG。

共用代码落点：后端api/schemas承载接口，services承载规则，core承载配置/记录，integrations承载Vidu及各AI适配；前端features承载界面和媒体，lib承载请求适配，api只放生成代码，tests存受控验证。每次schema变化都用现成CLI重新生成客户端并核对差异；不增加自定义脚本。

依赖T-029—049全部局部交付；G-CODE。责任为前后端联调者。将只读配置、真实运行模式的准备检查、创建/媒体/声音/输入/Codex/播读/继续/上下文/结束装配为一个网页流程，当前验证用受控替身而非真实模型。对照8个端点和最终OpenAPI重新生成客户端；关闭所有临时伪就绪、自动续开、暖场、自动重试和错误吞掉路径。

前置：独立测试数据库、单后端worker、目标桌面浏览器、测试专用非敏感问题、可控时钟/依赖事件。角色为内部测试者。

1. 缺配置打开页面/接口文档 → 明确缺项且外调0；用测试配置进入流程 → 唯一会话意图。
2. 提交并确认至少4轮模拟问答 → 每ID一次生成/播读意图；继续只解锁，第5问仅带第2—4轮，未确认轮不入窗口。
3. 注入各阶段超时/断线/失败、双击、旧结果和继续/结束竞争 → 正文提示、不自动重发、不污染新会话。
4. 在创建中/生成中/发送中结束并重启 → 取消拥有的进程、保留外部未知记录及预算，不恢复正文或自动新建。
5. 以真实运行模式但移除真实准备条件重新打开 → 开始不可用；测试替身不能成为实际ready依据。检查秘密脱敏与数据库无问答全文。

退出：所有必要局部/集成检查通过且有可复现日志、浏览器路径证据及启动/停止说明；记录仍为“模拟通过”，TC-016—020保持未执行。失败回到具体功能卡修复并只复验受影响链路，不增加范围或收费尝试。

### T-051 完成真实调用准入与配置冻结

依赖T-050；G-CALL须在第一笔真实调用之前满足。责任为用户确认业务取舍、实现者核对环境和计费配置。此任务包含可能计费的试听/资产处理/模型隔离探测，当前均未执行。

1. 不调用阶段：明确批准的账号、模型/provider/地区、样本数与所有准备/测试合计额度，核对计价与预留；准备本机目标浏览器和供应商后台可用的人工终止方法。
2. 在批准范围内完成送模图/云资产就绪核验，以同台词试听候选音色并由用户确定具体ID；冻结素材哈希、声音、人设与配置版本。只确认静态和就绪，不提前确认动态保形。
3. 用明确批准的非敏感受控样本验证本地Codex真实调用、最终事件与权限配置；不能读取未授权文件/开发线程或使用无关工具，只取消本次拥有的进程。失败停止，不以read-only/帮助页通过顶替。
4. 核对额度累计含以上所有尝试、无未决残留及结束路径可操作；满足后记录准入证据，再进入真实TC。为试听/准备产生的外部会话必须按同一结束核对规范收尾。

退出：具体素材/音色选定、真实能力与隔离有证据、额度足够且未决记录已核对；预算或可用能力不足即阻塞后续，不自动扩大额度。本任务不是产品验收，也不要求先通过尚未执行的TC-020。

### T-052 执行启动与真实媒体验收

依赖T-051。对应TC-016、AC-001—004，主责内部体验者/后端核对者。按计划07第09.1节执行：打开/刷新不收费 → 显式开始并核对唯一意图 → 不授予摄像头/麦克风权限仍取得真实首帧 → 用批准的首个冒烟问题取得实际首音 → 检查角色/画面和结束收尾。

首个问题同时作为T-053/TC-017样本复用，不额外扩大规模；因此首音不依赖“T-053已通过”这个循环前置。退出必须有真实首帧/首音、设备权限与会话证据；200、SDK joined或静态图不能通过。失败立即按已实现的结束路径清理并核对，后续测试暂停。

### T-053 执行问答与人工继续验收

依赖T-052。对应TC-017、AC-005—008/021—024，主责内部体验者/模型与接口核对者。复用首个样本，按计划07第09.2节覆盖对应AI真实回答（Codex只适用于ChatGPT候选）、人物实际播读、人设/长度、单次意图、人工继续及3轮上下文。边界/故障组合以T-050的模拟证据补充，不能为每个边界擅自真实调用。

退出必须有实际服务请求或本次CLI进程关联、经接受答案与听音对照、人工确认时间和上下文范围证据；工具事件或朗读问题不算回答。若批准规模不足以验证真实多轮，缺项标未执行/受阻，不用Mock补成全通过。失败不自动再问，核对额度及结束后再决定修复重测。

### T-054 执行声音与持续异常验收

依赖T-053。对应TC-018、AC-009—012，主责前端实现者/内部体验者。在批准会话内按计划07第09.3节验证真实静音/恢复、自动播放限制下的手动启声、键盘与正文提示；控制/媒体/轮询故障分别标真实或模拟注入。旧ID/revision不能污染画面或回复。

退出必须有实际听音变化和错误正文证据；video.play成功不能替代RTC声音恢复。未知声音状态不记为已静音，音频操作不释放轮次或停费。恢复失败则结束核对，不换新收费会话规避。

### T-055 执行结束残留与用量验收

依赖T-054。对应TC-019、AC-013—016及AC-023，主责后端核对者/值守人员。按计划07第09.4节验证生成中/回答中结束、重复结束、标签关闭/后端重启、创建未知和用量累计；危险/额外计费故障必须在批准范围，不能故意跑至超预算。

退出要求外部终态依据、未决处理和估计/实报/预留分栏可追溯；未知费用不能写0，后台全停限制及人工终止路径必须有记录。没有核对依据就保留end_unknown，阻止后续新建；不得删除账本使测试看似通过。

### T-056 执行短测观感与复现收尾

依赖T-055。对应TC-020、AC-017—020，主责用户/内部体验者进行观感评审，另一执行者按实际说明复现。按批准规模观察待机/短长回答/连续多轮的角色、服饰背景、声音与口型，逐样本记录首帧/首音/延迟及失败；不从小样本承诺P95或实时SLA。

退出要求配置冻结可追溯、真实动态/声音评审、复现与结束/用量核对证据。费用尚待结算或某能力未通过时明确未决，不能宣称全部完成；更新BLACKLOG任务状态与HANDOVER验收摘要，原始证据留output。若额度不够复现，标受阻并等补充决策，不自动续测。

以上T-052—056的步骤只在计划07维护，当前结果在HANDOVER更新，任务状态只在BLACKLOG。每次真实会话都必须有结束清理，不等到T-055才首次关停；若使用同一场串联几个TC，保留各TC独立证据与全场统一费用记录。
