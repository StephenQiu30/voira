# 23 回答长度与表达

需求编号：**FR-022**。范围：**网页PoC P0**。本文只维护这一项功能；[总索引](01-数字人MVP需求草案.md)维护阶段范围与共享约束。

## 01 问题与来源

用户需要听到简短自然的回答，避免漫长等候和播读。

来源：用户直接确认及既有网页PoC需求，2026-10-25整理。原编号/归属为FR-005/019，见[拆分前v0.9快照](history/01-数字人MVP需求草案-v0.9.md)；参考证据见[调研索引](../research/00-调研索引.md)。本次T-023仅拆分已有行为，不新增功能授权。

## 02 范围与边界

长度不是语速或响应延迟承诺，不加入自动摘要或长文朗读功能。

依赖或协作：FR-019/005。跨功能约束引用[共享NFR](01-数字人MVP需求草案.md#05-非功能性需求)，不在本文复制第二份架构或接口契约。

## 03 功能要求

1. 默认2—3个短句、约40—100个汉字，简单问题允许更短，最多150个Unicode码点。
2. 采用自然口语，不朗读Markdown或工具输出；不为凑字数填充内容。
3. 完整答案须校验再交给人物；超长或无效答案不截断半句话，不自动二次调用凑合输出。
