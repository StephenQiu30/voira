## 01 用户、问题与当前阶段

内部开发者和体验者先验证本机网页数字人闭环；建议一个目标桌面浏览器、一个角色、一个活动会话。真实音视频、回答与结束需要真实证据；静态设计、帮助输出、Mock和第三方演示不代表本项目通过。

## 02 已确认方向与变更记录

- 网页PoC优先，直播后置，覆盖旧“双端一期”安排。
- Vidu、蓝色大肥鱼、人物/背景合成、提问后回答已确认；角色视觉映射不等于连接同名大模型。
- 本地优先，由本机Codex生成回答，接入协议从简；本机调用不代表离线推理。
- 音色方向、人设、回答长度、人工继续、最近3轮上下文已确认，分别归入FR-020—024。
- 预算、账号和测试规模等实际调用前再定；当前仍只整理文档，不写代码。
- 用户要求“每一个功能是一个单独的需求”，从v0.10起按独立功能文档维护。
- 2026-10-25 T-078：确认本次会话完整记录，不做长期历史；预留独立干净播出视图，自动读评论后续实现但页面先设计。详见FR-030与FR-003/010/012；只授权文档，不展开实现。

## 03 当前PoC范围与成功定义

当前链路：固定角色 → 开始会话 → 网页媒体可用 → 文字提问 → 本地Codex生成答案 → Vidu播读 → 人工听完后继续 → 结束核对。各步的业务规则只在对应功能文档维护。

直播、外部评论、商品/礼物、主动暖场、换装动作、桌面打包等仍后置。预算未定不阻塞已授权文档整理；真实调用前落实账号、素材与额度。当前没有可运行应用或真实TC通过记录。

## 05 非功能性需求

| 编号 | 类别 | 当前PoC约束与记录方式 |
|---|---|---|
| NFR-001 | 响应性能 | 记录创建到网页首帧/首音、文字提交到首音、失败与超时；少量样本先列明逐条结果，不用小样本P95冒充稳定性能。原直播的5秒/30秒门槛不沿用为当前通过条件 |
| NFR-002 | 人物与媒体 | 固定角色和短句/长句观察画面、音色、口型与连续性；记录无声、黑屏、冻结、明显脸部/衣着异常；参考效果作为评审方向。原25fps/150ms为历史研究值，当前先收集实测与样例 |
| NFR-003 | 异常处理 | 网络断开、页面刷新/关闭、服务端异常不能一直显示可用；可明确结束或提示重试；旧会话结果不得污染新会话。不要求180秒无感恢复、跨会话记忆、连续2小时或自动续接直播 |
| NFR-004 | 访问与内容 | 仅用获授权素材，页面明确标识AI数字人；长期密钥仅后端持有，不放地址栏/浏览器代码或普通日志。已确认本地优先；网页、后端及状态在本机，模型调用仍可能发送必要文本到云端；若需远程分享，再补访问限制，不默认公网无鉴权开放 |
| NFR-005 | 测试成本 | 真实调用前明确账号及测试预算；分别控制Vidu时长/费用与Codex调用次数/实际费用，重试累计；结束状态与供应商用量分开核对。保留停费边界，不建设商业结算系统 |
| NFR-006 | 浏览器可用性 | 先支持一个目标桌面浏览器；开始/结束/静音/文本输入可操作，加载与错误状态明确；声音自动播放被阻止时可手动恢复。手机适配与多端压测后置 |
| NFR-007 | 可复现 | 记录配置版本、会话与输入输出时间、异常及终止依据；给出实际启动/停止说明，另一执行者能复现网页闭环。供应商“说完”不等于本地已播放完，无法观测则标未知 |

已确认工程规范保持不变，详见PROJECT及两端规范。当前不实施直播分发、复杂数据库/队列、独立媒体出口和自动审核系统；T-078仅预留独立播出视图并设计评论操作页；是否引入存储等基础设施由最小设计说明必要性。
