# 20 本地Codex回答生成

需求编号：**FR-019**。范围：**网页PoC P0**。

## 01 问题与来源

本机网页需要受控的Codex接入能力。T-118确认七位形象与对应AI一一绑定后，本功能仅作为ChatGPT／OpenAI角色的候选实现；其他六位按[FR-031](32-七位角色与AI服务绑定.md)接入各自服务，不由Codex代答。

来源：用户直接确认及既有网页PoC需求，2026-10-25整理。

## 02 范围与边界

本机进程不等于离线推理；人设、长度与上下文独立维护。

依赖或协作：FR-021/022/024/025。

## 03 功能要求

1. 本机后端调用Codex，仅取得成功终态且校验后的完整最终回答；推荐每轮一次exec，不强制MCP。
2. 固定版本、模型和受限配置；不继承开发线程、任意本地文件或无关工具权限。
3. 用户问题通过受控文本输入传入，不能作为shell命令或配置；中间事件和日志不能播读。
4. 失败、超时或结束后的结果不下发，不自动重试或切到Vidu生成答案；只取消本次拥有的进程。

## 04 确认状态与剩余问题

原本地Codex路线保留在适用角色内；七位绑定的新范围优先。具体模型、认证和运行隔离尚未验证，CLI已安装不代表角色服务接入完成。

关联问题：Q-006。
