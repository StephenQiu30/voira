# 32 七位角色与AI服务绑定

需求编号：**FR-031**。范围：**当前网页产品；七位角色一一绑定对应AI的方向已确认，连接配置与交互细节待落实**。

## 01 问题与确认来源

形象选择完成后，用户需要真正与该形象对应的AI交流。2026-10-26用户明确：数字人仍是核心需求，七个已设计的AI形象各自对应一个接入的AI。不能由同一个Codex为所有品牌代答，再仅替换形象或提示词。

这项新决定扩展原单Codex／单角色PoC：保留数字人、网页优先和本地后端，回答来源改为选中角色绑定的服务。[FR-019](20-本地Codex回答生成.md)保留为ChatGPT角色的本地Codex接入候选，不再作为所有角色的必经实现。

## 02 范围与边界

| 角色ID／显示名 | 对应回答服务 | 约束 |
|---|---|---|
| deepseek／DeepSeek | DeepSeek | 不以OpenAI模型代答 |
| gemini／Gemini | Gemini | 使用对应服务的实际模型 |
| claude／Claude | Claude | 可复用合法可调用的API或Claude Code入口，接法待核验 |
| grok／Grok | Grok | 使用对应服务的实际模型 |
| chatgpt／ChatGPT | OpenAI模型 | 可复用本地Codex；ChatGPT产品登录或名称不直接证明后端调用可用 |
| kimi／Kimi | Kimi | 服务接入与形象素材准备分别验收 |
| qwen／Qwen | Qwen | 服务接入与形象素材准备分别验收 |

七项是产品目标，不代表七项已经接通。不要求同时创建七个数字人媒体会话；继续同一时刻一个活动会话。没有新增跨会话历史、多用户账号、双AI群聊或原生iOS／Android交付承诺；参考教程的这些功能不是本次确认内容。

## 03 功能要求

1. 每个角色有唯一的当前回答服务绑定，实际模型名称和配置版本可核对。品牌、角色人设、模型版本、音色、送模资产分别管理。
2. 优先复用已有、合法可调用的服务连接。浏览器只调用Voira后端，不能持有供应商密钥或任意指定上游地址；Codex聊天中可用的插件不自动成为FastAPI的可调用服务。
3. 选中角色后检查该角色的AI、素材、声音及额度；只依据该角色缺项反馈可用性，不要求其他六项同时就绪。静态图片可展示不代表能交流。
4. 同一次会话固定角色、回答服务、模型、人设和媒体配置。建议切换交流对象先结束并核对旧会话，再以空上下文开启新会话；不在生成或播读中热切模型。
5. 角色对应AI生成的完整最终答案进入统一校验，再交由[FR-005](06-人物回答播读.md)播读。Vidu负责人物音视频，不重新回答，不替代失败的AI服务。
6. 服务失败、鉴权失效、超时或结果未知必须明确反馈；不得静默跨品牌降级、伪造回答或重复调用。正文与状态不得串入其他角色／会话。
7. 沿用[FR-024](25-最近三轮上下文.md)的三轮已确认上下文和[FR-030](31-本次会话完整对话记录.md)的当前页面完整记录；既有服务中的个人聊天／开发线程不得导入产品会话。

## 04 确认状态与剩余问题

已确认：七位角色与七个对应AI一一绑定，数字人继续保留。建议：会话中固定绑定，结束后切换。当前仓库没有七服务的运行适配器；已安装CLI和已有账户不能替代项目联调证据。

**Q-014：** 每项服务的现有连接归属、API或CLI入口、实际模型与版本、后端认证引用、可用权限及限额仍需落实；此处只记录配置引用，不收集或保存密钥值。优先核对既有连接，再决定是否需要新接入。账号与调用额度继续由Q-006／FR-025负责，不重复开放已确认的三轮上下文等选择。
