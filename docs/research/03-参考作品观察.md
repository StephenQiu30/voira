# 03 参考作品观察与证据台账

调查窗口：2026-10-24—25（Asia/Shanghai）。此文件区分实际观察、作者声明、技术推断和待验证项。

## 01 调查问题

1. 参考作品是什么产品、是什么人物风格？
2. 它展示了哪些可借鉴的功能与流程？
3. 它是否证明真实直播画质、口型和连续运行？
4. GitHub项目如何实现，哪些机制可复用？
5. 同时做自有网站与外部直播需要补哪些层？
6. 当前官方接口、价格和框架能力是否支持建议路线？

## 03 工具与取证边界

| 工具 | 本次实际使用 | 证据性质 |

| REA / reverse-engineer-anything | 临时Chrome导航到指定作品，等待5秒，采集截图与accessibility，工具结束浏览器 | 受控页面观察；没有运行映播，也没有观察其内部后端 |

| 浏览器UI | 打开抖音页面公开列出的第2—10张图片并读取视觉内容 | 静态图片观察，未操作图中的产品 |

| 图序 | 本次实际读到的内容归纳 | 对本项目的决策影响 |
|---|---|---|
| 01 | 产品总览，横屏工作台与人物居中的静态截图 | 借鉴人物主体，不复制品牌、真人素材或整个桌面产品 |
| 02 | 图片/音色/人设，经Vidu会话到实时媒体，再用独立窗口及评论流程直播 | 当前采用前半段；输入改为网页提问，外部播出后置 |
| 03 | 多轮界面改造、信令/声音、消息问题、双端桌面包和趣味素材 | 工程进度叙述不是所有能力已验证；不改本项目网页工程栈 |
| 04 | 自己开播的用户目标、Mac使用环境、评论/礼物/商品及交付包 | 是参考产品原始需求；我们保留功能候选，当前用户仍是内部PoC体验者 |
| 05 | 不滚动评论区导致同批消息反复进入；要求去重、待处理项超时及当前回答完整说完 | 当前转为输入ID去重、单请求串行；60秒仅作为未来队列候选阈值 |
| 06 | 人物居中、横竖画幅、面板能关闭/收起/移动 | 当前先落实嘴脸安全区；工作台编辑和画幅切换后置 |
| 07 | 人物/画幅、消息处理、商品和手动话术分区；工作台预览与独立实时窗口不同 | 必须区分静态预览和真实媒体；不把图中控件视为已测试交互 |
| 08 | 四条评论OCR示例，采集、去重、排队和口播是分开的环节 | 读取成功不证明回答成功；本轮不增加OCR或事件来源权限 |
| 09 | 商品资料由操作者确认，服饰搭配完整，道具按启用/触发/恢复组织 | 原始需求分别登记商品、换装、道具恢复；卡片管理不能证明动态效果 |
| 10 | 画面、声音、评论、回复及收播分别核验，图文演示未接收费实时会话 | 网页版本改为画面、声音、文字、回答、结束；口型/延迟/稳定仍须真实测试 |
