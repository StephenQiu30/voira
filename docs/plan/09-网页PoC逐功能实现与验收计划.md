# 09 网页PoC逐功能实现与验收计划

**最新授权（T-084）：** 用户已允许从前端布局开始实现。本批开放应用初始化、BasicLayout、人物选择页与主题／选择交互；不依赖后端schema，不包含HTTP客户端、真实会话、直播队列或模型调用。T-030仅页面壳部分由T-084先行，原任务整体不标完成。其余业务门槛保持。

**范围增量：** T-078新增FR-030完整会话记录，当前17项需求；下文原16项实施任务保留，补充范围与门槛见第11节，未启动实现。

本轮T-028仅拆任务，**不写代码、不安装依赖、不创建运行数据库、不调用模型**。28项后续任务已分配编号，执行状态只维护在[BLACKLOG](../../BLACKLOG.md#27-网页poc后续实现与验收队列)。原[计划07](07-网页数字人PoC验证计划.md)继续定义TC-016—020及真实证据，本计划定义谁先做什么、依赖与交付标准。

## 01 目标与规格基线

目标是在本机网页跑通蓝色大肥鱼：预览 → 开始 → 真实画面/声音 → 提问 → 本地Codex回答 → Vidu text_tts → 人工继续 → 最近3轮上下文 → 结束核对。16个当前功能逐一拆分；13个后置功能不排实现任务。

基线：[requirement索引v0.10](../requirement/01-数字人MVP需求草案.md)及其16份当前功能、[设计索引](../design/00-功能设计索引.md)DES-018—033（各v0.1）、[共享设计v0.6](../design/03-Vidu网页PoC最小业务设计.md)DES-012—017、[PRD v0.6](../prd/01-网页数字人PoC产品与验收标准.md)US-001—005/AC-001—024。共享7项NFR不变；实际实施时再次核对版本变化。

技术栈、目录与生成协议沿用[PROJECT](../../PROJECT.md)及前后端规范。任务中的代码路径均为拟落点，不表示文件已经存在。资源/人选/可用容量未提供，不虚构负责人姓名、点数、工期或Sprint承诺；先按依赖交付，排期时再据实际容量预留15%—20%不确定性缓冲。

## 06 按功能实施任务卡

每张卡只有一个主FR；“后端→前端→联调”是本功能交付顺序。前端可先做模拟显示，最终必须完成联调；无独立前端功能的条目明确复用现有页面，不人为扩围。共同前置G-CODE，各任务验收在T-032受控依赖下完成；执行状态仅在BLACKLOG。

共用代码落点：后端api/schemas承载接口，services承载规则，core承载配置/记录，integrations承载Vidu/Codex；前端features承载界面和媒体，lib承载请求适配，api只放生成代码，tests存受控验证。每次schema变化都用现成CLI重新生成客户端并核对差异；不增加自定义脚本。
