# 07 网页数字人 PoC 验证计划

对应[需求索引v0.10](../requirement/01-数字人MVP需求草案.md)。用户已确认当前先跑通数字人网页，直播后置。本计划替代[原双端PoC](05-双端PoC验证计划.md)在当前阶段的作用；具体测试尚未执行，不代表已经有可运行应用。v0.4落实Vidu、蓝色大肥鱼、合成画面与提问后回答的确认，新增最小业务设计及产品验收追溯；第06—07节保留当时研究历史，不再作为当前未决状态。

## 01 目标与范围

在一个目标桌面浏览器中完成：打开网页 → 开始一个数字人会话 → 真实画面和声音可用 → 输入文字后人物回应 → 结束会话并核对终止结果。

采用一个授权角色、一套形象和一个活动会话。互动已确认为文字提问后人物回答，由本地Codex生成答案、Vidu text_tts播读；不开放面向用户的手动台词功能。无外部平台、OBS、RTMP、多观众、弹幕池或独立直播控制台验收。

本计划不执行旧TC-001—010的直播验证。TC-011—015已用于工程规范核验，因此当前使用TC-016—020。测试编号不复用，历史资料保留。

## 03 验证顺序

1. **网页与控制接口**：按既有Next.js/FastAPI规范跑通页面、开始/结束、文本输入、状态和错误反馈；可先Mock，不宣称数字人已运行。
2. **单会话媒体**：接真实供应商，在网页接收首帧与首音；自动播放受限时验证手动开启声音。失败则修连接，不添加直播功能。
3. **单次文字与连续短测**：输入短句/长句观察回应、口型及状态；忙时禁用或明确拒绝新请求；无重复发送、旧结果污染和未知任务自动重播。
4. **结束与异常**：主动结束、重复开始、网络中断、刷新/关闭页面和启动失败后核对残留会话；结束未知时不再新增生成，人工核对用量。
5. **记录结果**：保存最小复现步骤、Codex生成与Vidu播读分别计时和计量、逐条样本结果、错误与结束依据；先评审网页闭环，再另行决定是否进入直播阶段。

停止条件：接收不到真实音视频、无法确认会话终止、达到预算/时长上限或出现无法控制的异常时停止新增生成。排障不自动增加测试费用或申请外部直播权限。
