# 01 网页数字人PoC产品与验收标准

**当前增量：** T-078新增本次完整记录，当前17项网页需求；直播输出与评论页面仅先做结构设计。新增US-006—008、AC-025—033及评审边界见第12节；原有实施与真实验收记录保持。

## 01 概述

声伴Voira首轮让内部体验者在网页与蓝色大肥鱼进行文字问答，看到真实人物画面、听到实际回答，并明确结束会话。用户已选定Vidu和人物/背景合成画面，并确认本地优先、PoC由本地Codex生成回答；本轮只整理文档，不写代码或调用付费服务。

上游：[需求索引v0.10](../requirement/01-数字人MVP需求草案.md)、[DES-012—017](../design/03-Vidu网页PoC最小业务设计.md)；执行与证据：[计划07](../plan/07-网页数字人PoC验证计划.md)。

## 02 背景

已有立绘、Figma及参考源码，尚不能证明本项目网页真实数字人可用。抖音[参考图文](../research/03-参考作品观察.md#07-十图复核与需求转换2026-10-25)提示了重复消息、回答被打断、状态难定位等问题，其截图未接真实Vidu会话。我们先验证网页闭环，把直播采集、调度和分发留到后续。

## 03 目标与成功指标

| 用户结果 | 统计口径与候选通过条件 | 测量方式 |
|---|---|---|
| 完成真实问答闭环 | 同一配置完成开始、真实画面/声音、问题引出语义相关回答、结束核对；每个环节须有真实证据 | TC-016—019，未执行 |
| 回答有序且可辨识 | 已批准样本逐条记录；同一次提交无重复Codex调用或播读下发、普通后续输入不抢占；明显变脸/黑屏/无声记失败 | TC-017/020；样本量依Q-005，不编造成功率 |
| 可复现且能核对结束与用量 | 另一执行者按相同版本复现闭环；终止未知及未核对费用均不得写为成功 | TC-019/020；额度依Q-006 |

首帧、首音和回应时间逐样本记录，现阶段不承诺P95、25fps或150ms同步指标。本文AC是可评审标准，尚无通过成绩或完整用户验收结论。

## 04 用户与场景

首版只有内部体验者和负责验证的开发者，建议一个本机桌面Chrome、一个角色、一个活动会话。体验者可输入文字、启声/静音、人工确认听完和结束；开发者可检查配置、日志及供应商终态。不提供公开观众、运营后台或远程共享账号。

## 05 价值主张

- **谁**：内部产品、设计和工程体验者。
- **为什么**：需要判断现有角色是否能在自有网页实时回答，而不仅是展示静态稿。
- **之前怎么做**：分别查看设计图、第三方演示和接口资料，缺少同一配置的真实闭环证据。
- **如何解决**：固定角色和音色，通过一个网页完成开始、提问、听答和结束核对。
- **之后得到什么**：能据真实样例判断人物质量、交互可用性与费用边界，并定位失败阶段。
- **替代方案**：仅用供应商演示或预录视频可观察效果，但不能证明本项目网页控制与终止行为。

## 06 用户故事与验收标准

### 06.1 US-001 开始一次可辨识的真实体验

作为内部体验者，我希望明确看到蓝色大肥鱼并开始真实会话，以便判断这是不是实际可交互的人物。讨论：单角色、合成画面、声音与媒体分别判断。来源FR-001/002/011、NFR-004/006；设计DES-012/013。

| 编号 | 给定 / 当 / 则 |
|---|---|
| AC-001 | 给定固定角色配置，当查看预览并开始，则显示蓝色大肥鱼、AI标识与同一送模版本；未开始明确是静态预览，真实首帧后切换整体视频且嘴脸不受遮挡 |
| AC-002 | 给定未开始或配置/额度缺项，当打开页面、接口文档或刷新，则不产生收费会话；缺项有明确说明、开始不可用 |
| AC-003 | 给定点击开始或响应丢失，当重复同一创建意图，则只有一条本地意图且不会重复调用创建；结果未知时禁止另开，不能显示启动成功 |
| AC-004 | 给定已核对账号与素材，当建立真实会话，则无需摄像头/麦克风权限即可接收真实首帧并实际听到声音；创建200或WS ready不能单独判通过 |

### 06.2 US-002 问一个问题并完整听到回答

作为体验者，我希望人物回答我的问题，且不会重复或被下一问打断。讨论：首轮只做问答；无服务端播放结束证据时，采用用户已确认的人工继续方式。来源FR-004/005/019/021/022/023/024、NFR-001/002/007；设计DES-012/014。

| 编号 | 给定 / 当 / 则 |
|---|---|
| AC-005 | 给定可输入状态，当提交空白或超过500码点的文字，则页面和后端拒绝且不下发；有效边界文字可提交，错误不丢失草稿 |
| AC-006 | 给定一条测试问题，当发送，则人物按已确认的温和、轻松、略俏皮AI伙伴人设给出语义相关回答，不冒充真人/模型厂商或声称未接入能力，并有实际声音/对应口型；回答必须来自本地Codex，Vidu只负责播读与驱动；不得以朗读问题、预录回答或猜测字幕通过 |
| AC-007 | 给定同一次提交，当重复点击/重试相同输入ID，则返回原记录且最多一次Codex启动意图和一次Vidu播读下发意图；相同ID不同内容拒绝，释放上一轮后用新ID主动重问相同文字不被永久去重 |
| AC-008 | 给定当前输入占用，当普通提交下一问，则提示忙并保留草稿；体验者实际听完后可确认继续，只解锁、不自动发送草稿，记录为人工确认。无回应/断线/未知不自动重播、不伪造已完成，结束始终可用 |

### 06.3 US-003 控制声音并理解异常

作为体验者，我希望声音和连接异常有清楚反馈，以便自主处理当前体验。讨论：本地静音不影响供应商计费；按现有无边框主题保留焦点和持续错误。来源FR-006/011/026、NFR-003/006；设计DES-015。

| 编号 | 给定 / 当 / 则 |
|---|---|
| AC-009 | 给定人物在回答，当静音后恢复，则本地声音状态准确，不创建新会话、不声称已停费，也不据静音判断回答结束 |
| AC-010 | 给定浏览器阻止自动播放，当点击开启声音，则可以听见真实音频；若仍失败有持续提示。开始、输入、静音和结束均可键盘操作且焦点可见 |
| AC-011 | 给定控制/媒体/状态查询异常，当断网或模拟依赖失败，则页面不继续显示可用，错误留在正文，停止新增输入并提供结束/核对入口 |
| AC-012 | 给定已结束或新会话已开始，当旧会话事件或旧revision响应晚到，则不能更换当前画面、回复或状态；刷新不自动开新会话 |

### 06.4 US-004 确认结束并守住试验用量

作为体验者和验证者，我希望结束后能查明外部会话是否停止，以便控制试验消耗。来源FR-002/007/008/025、NFR-003/005；设计DES-016/017。

| 编号 | 给定 / 当 / 则 |
|---|---|
| AC-013 | 给定活动会话，当结束，则立即禁止新输入、停止本地媒体、取消本轮拥有的Codex调用、丢弃晚到答案并请求Vidu挂断；只有供应商查询ended或可追溯人工核对证据才显示已结束 |
| AC-014 | 给定挂断、创建或查询超时，当无法确定外部结果，则显示未知、保留ID/意图并阻止新建；重复操作不清空该记录或生成新会话 |
| AC-015 | 给定未结清会话，当刷新/关闭页面或重启后端，则按租约/持久化记录清理和核对；无live_id的创建未知不能被丢弃。后端全停期间的人工终止路径须实测并记录限制 |
| AC-016 | 给定经批准的试验上限，当达到Vidu会话/累计限制、Codex调用次数/额度上限或余额不足，则停止新增生成并触发必要终止；重试/重启/新会话不清零同一run_id用量，结算未知保持预留 |

### 06.5 US-005 判断效果并让他人复现

作为产品验证者，我希望比较同一角色的真实表现并复现问题，以便决定继续还是修改方案。来源FR-001/008/011/020、NFR-001/002/004/005/007；设计DES-012/017。

| 编号 | 给定 / 当 / 则 |
|---|---|
| AC-017 | 给定冻结的母版、送模图和声音配置，当观察待机、短回答、长回答和连续多轮，则保持同一角色/画风/关键服饰背景及同一已选音色；声音符合自然清楚的成年普通话女声方向，轻松且不过分幼态，具体voice ID需先试听评审；明显变脸、持续异常口型、无声或冻结标失败并记录时间点 |
| AC-018 | 给定获批准样本，当进行短测，则逐条记录问题、实际回答或人工摘要、首帧/首音、延迟和异常；无精确结束信号写未知或人工确认，不以API成功代替回答成绩 |
| AC-019 | 给定网页、网络响应和排障记录，当检查凭据与来源，则无长期密钥、控制令牌或短期RTC凭据泄露到URL/普通日志，素材来源可追溯；不默认录音录像或长期保存提问全文 |
| AC-020 | 给定配置版本、实际启动/结束说明和用量记录，当另一执行者复现，则能完成同一真实闭环并查到结束依据；估算与供应商实际用量分栏，待结算不得写零费用 |

### 06.6 US-002补充：本地Codex回答的验收

来源FR-019/022/024、NFR-001/003/004/005/007；设计DES-014/016/017；沿用US-002，不新增故事编号。

| 编号 | 给定 / 当 / 则 |
|---|---|
| AC-021 | 给定可用本机Codex配置，当提交问题，则实际在本机启动本项目拥有的Codex调用，记录版本/模型/输入关联；最终答案由其产生，再经Vidu text_tts播读，不调用Vidu text_dialog重答，不把CLI帮助通过当生成通过 |
| AC-022 | 给定Codex输出包含中间事件，当取得最终答案，则只有成功终态且通过格式/长度校验的完整回答可播读；默认2—3短句、约40—100字，简单问题允许更短，最多150个Unicode码点；超长或无效答案不截断半句话、不自动二次调用；网页“生成的回答”不冒充已播出字幕，真实听音与答案语义一致，工具/日志不被播读 |
| AC-023 | 给定生成失败、超时、无效答案或用户已结束，当发生异常或晚到结果，则停止本轮并清楚说明，绝不发往Vidu、自动重试或换供应商；只取消本次拥有的进程，不影响其他Codex会话；取消不自动记为上游零费用 |
| AC-024 | 给定已确认的短期记忆规则，当多轮追问、重启或开始新会话，则只使用当前会话最近3轮已人工确认的完整问答加当前问题；不足3轮用已有轮次，首次为空，超过3轮移出最旧一轮；失败/未确认轮次不加入，结束/重启清除正文；不读取其他聊天/开发目录或调用无关工具，须有实际受限配置验证，单靠read-only或提示词不算通过 |

### 06.7 假设与待确认

2026-10-25用户已按推荐确认音色方向、人设、回答长度、人工继续和最近3轮上下文；Q-012/013关闭，Q-010/011保持关闭。对应规格落在AC-006（人设）、AC-008（人工继续）、AC-017（音色方向）、AC-022（回答长度）及AC-024（上下文），确认的是要求而非测试通过。剩余决策统一见[需求第12节](../requirement/01-数字人MVP需求草案.md#12-网页poc待确认清单与推荐2026-10-25)：具体voice ID、送模版本和真实观感待评审；短测规模、账号与预算等在实际调用前确定，Q-008保存建议仍未新增确认。本次不批准代码实现、完整PRD或付费调用。

## 07 发布范围与停止条件

## 11 分阶段验收与剩余决策

1. **公共基础与局部功能交付**：前后端实际实现、生成契约一致、受控依赖测试和必要浏览器状态检查通过；每项交付关联独立任务与AC。此阶段不能把真实TC标为通过。
2. **模拟集成T-050**：一个页面贯通全部16项功能及必要异常，证明调用次数、状态与依赖正确；不证明真实画面、音色、语义、权限隔离或费用。
3. **真实准入T-051**：实际调用前确认G-CALL，再在批准范围完成具体素材/音色选定、真实配置/隔离和结束路径核验。方向已确认的五项选择不重问；预算/账号/规模仍按原安排在调用前确定。
4. **真实产品验收T-052—056**：按TC-016—020完成真实启动、问答/继续/上下文、声音/故障、结束/用量、观感/复现。每次会话都要收尾；模型任务完成、WS成功或Mock成绩均不替代实际听音与终态。

当前只批准任务文档整理，所有实现/真实验收任务未执行。未来用户允许代码后可先完成模拟阶段，缺具体voice ID、素材冻结或真实额度不阻塞受控实现；真实运行模式必须保持缺项锁定。没有团队人数、容量和性能实测，不给出虚构工期、点数或SLA。

剩余用户决策：具体voice ID和送模版本，实际测试账号/模型、样本规模和预算；动态观感在真实测试中评审。SDK兼容、Codex权限隔离、取消和供应商核对属于实现/验证责任，不要求用户替工程验证结论。失败回到对应功能修复；范围/验收改变则先更新上游需求与设计。
