# 01 前端开发规范

## 01 适用范围与依据

适用于 [frontend](../../../frontend/README.md)。目录与跨端契约见 [PROJECT](../../../PROJECT.md)，配色、字体、间距和材质见 [DESIGN](../../../DESIGN.md)。本文约束组件实现和前端平台命令，不另设配色表。

技术栈为 Next.js + React + TypeScript、shadcn/ui（Radix）、Tailwind CSS、Prettier、ESLint、Axios、Zustand、`@umijs/openapi`。组件写法遵循 [shadcn/ui](https://ui.shadcn.com/docs/cli)；预览、环境与部署命令遵循 [Vercel CLI](https://vercel.com/docs/cli)。2026-10-27按这两份用法核对本项目约定。不因使用 Umi OpenAPI 生成器替换 Next.js，也不因引用 Vercel CLI 表示站点已经托管。

## 02 目录与依赖方向

| 路径（相对 frontend） | 职责与约束 |
|---|---|
| src/app | 页面、布局、路由状态和全局样式，保持页面装配轻量 |
| src/features | 经确认的业务功能，各自组织界面、Hooks与调用编排；不预建未获批准的功能 |
| src/components | 跨功能共享组件；ui 子目录只放 shadcn 组件源码 |
| src/hooks | 复用 Hooks，不作为业务函数杂物目录 |
| src/lib | Axios 请求适配与基础工具，服务端专用模块明确隔离 |
| src/api | Umi OpenAPI生成的API类型和请求，禁止手改 |
| src/stores | Zustand stores，按实际共享状态拆分 |
| src/types | 前端展示等专属类型，不重复生成 DTO |
| public、tests | 公开资源及测试；不建立脚本目录 |
| components.json | shadcn CLI 的项目配置，随组件变更一起维护 |

依赖由页面/功能流向共享组件、请求层和基础工具。`src/components/ui` 不导入业务功能或 store，`src/api` 不反向导入界面。React 组件名使用 PascalCase，普通函数与变量使用 camelCase，Hook 使用 `use` 前缀；自有普通文件使用 kebab-case，保留 Next.js 约定的特殊文件名。

类名合并使用已安装的 `cn` 包：`import { cn } from "cn"`。不另写一份 `@/lib/utils` 的 `cn()`。CLI 若生成 `@/lib/utils` 导入，在同一次改动中改回 `cn` 包。

## 03 渲染与状态

- App Router 默认使用 Server Components；状态、事件、Zustand或浏览器 API 所在的小范围交互入口声明 `use client`，避免把整个布局无条件放入客户端边界。
- Server Components 不读取浏览器 API；服务端专用模块使用 `server-only` 边界。传给 Client Components 的 props 必须可序列化且不含秘密。
- 局部表单和短生命周期交互使用 React 状态；分享链接所需的筛选用 URL；跨组件共享的客户端状态用 Zustand。服务端数据加载在页面/功能层组织，明确加载、空、错误与刷新结果，不默认另引入一套状态框架。
- SSR 下不得把每个请求/用户的 Zustand 状态写入服务器模块级共享单例；需要 SSR 初始化时按请求/组件树创建 store，保证 hydration 一致。
- Zustand 不持久化长期凭据、服务端业务事实或未知任务的自动重放指令；持久化 UI 偏好时使用显式白名单与版本迁移。主题键保持 `voira-theme`。

## 04 shadcn 组件

### 已锁定的安装

`components.json` 当前为 `radix-nova`、`baseColor: neutral`、`rsc: true`、`tsx: true`、`iconLibrary: lucide`，样式入口是 `src/app/globals.css`。底层是统一包 `radix-ui`，例如 `import { Slot } from "radix-ui"`。不混入 Base UI 同名组件，不改用 `@radix-ui/react-*` 旧包。

不重新执行 `shadcn init`，不切换 preset，不把 style 改成 `new-york` 或 `base-ui`。初始化只在新建应用时使用，并且必须非交互：`npx shadcn@latest init -d --base radix`。`-y` 不能代替 `-d`。CLI v4 已删除 `--style`、`--base-color`、`--src-dir`、`--no-base-style`、`--css-variables`，不要再传。

在 `frontend` 目录添加组件：

```sh
npx shadcn@latest add button dialog
```

添加后核对导入、依赖和焦点样式，再按 DESIGN 去掉装饰性边框和阴影。不手抄上游源码绕过 CLI，不执行 `add --all` 预装未使用组件。

### 主题如何接到 DESIGN

语义色只使用 `globals.css` 里已有的 `--background`、`--foreground`、`--primary`、`--muted`、`--accent`、`--destructive`、`--ring` 和玻璃变量，通过 `bg-background`、`text-foreground`、`text-muted-foreground`、`border-border`、`ring-ring` 引用。不把 shadcn 示例里的 oklch zinc 面板色写进组件，不增加第二套强调色。

`--radius` 维持 `1rem`。组件内部只用现有 `--radius-md`、`--radius-lg` 或组件已声明的 size，不临时写一套互不相关的圆角。

`@theme inline` 在解析期展开变量，不能写成 `--font-sans: var(--font-sans)` 或 `--font-sans: var(--font-geist-sans)`。字体族应写成字面量 `"Geist", "Geist Fallback", "PingFang SC", "Microsoft YaHei", sans-serif` 和对应的 Geist Mono。当前 `globals.css` 仍引用运行时变量 `--font-geist-sans`；下次改字体声明时改成字面量，并把 `GeistSans.variable` 留在会注入该变量的根节点上。正文排版继续遵循 DESIGN，不另换字体。

根布局保留 `TooltipProvider`。图标使用 Lucide，尺寸与现有按钮一致，默认 `size-4`。图标按钮必须有可访问名称。

### 组合

优先复用已有组件，而不是再写一套无语义的 `button`、`input` 或带边框的 `div`。

| 场景 | 使用 |
|---|---|
| 人物舞台与姿态 | 现有 layout 与 `Tabs`；人物层不套 Card |
| 主操作 / 次操作 | `Button` 的 `default` 与 `ghost`；舞台上已有的 `glass` 变体留在 `button.tsx` |
| 需要说明的浮层 | `Dialog`，含标题和描述 |
| 删除或不可撤销确认 | `AlertDialog`，不用普通 `Dialog` |
| 表单 | `Label` 绑定控件；placeholder 不代替标签 |
| 状态 | `Badge`；颜色不能是唯一提示 |
| 头像 | 本地 `Avatar` 已声明 `default`、`sm`、`lg`，只用这些值；其他组件没有 size 属性时用 className |
| 管理或设置页 | 获准后用 `Tabs` 分组，一组一块表面；不在卡片里再套卡片 |
| 空、加载、错误 | 与内容同区显示；加载用 `Skeleton`，错误留在相关正文，不只用 Toast |

密度在同一页内统一：舒适用 `gap-6`、`p-6`，紧凑用 `gap-4`、`p-4`，字号保持 `text-sm` 与 DESIGN 的 16px／14px 正文分工。去掉装饰边框时保留 `focus-visible` ring、选中、禁用和错误态。

不采用的默认做法：全页渐变、每块表面都做玻璃、多个强调色、用原始表单控件替换已有组件、为了示例而增加仪表盘卡片。人物、舞台和已确认的轻量玻璃以 DESIGN 为准。

## 05 Axios 与 Umi OpenAPI

- 业务组件通过生成服务及功能层调用接口，不各自创建 Axios 实例。统一适配层定义 baseURL、超时、AbortSignal、错误归一和实际鉴权传递方式。
- 生成 request 的 `params`、`data`、headers、responseType及返回值必须逐项映射。Axios 的 `AxiosResponse<T>` 与生成方法声明的 `T` 不等价；适配层返回契约要求的数据，不能靠类型断言掩盖不一致。
- 浏览器与服务端请求上下文分开处理。SSR 鉴权按请求传入，禁止把用户 Cookie/Authorization 写进共享 Axios defaults；是否跨域携带 Cookie 根据后续鉴权与 CORS/CSRF 设计决定。
- 错误保留 HTTP 状态及可供排障的请求标识，不将所有失败显示成成功或空列表。取消与业务失败分别处理；不在拦截器重复弹出多次提示。
- 有副作用的请求不默认重试。直播开停、指定播报等命令若进入已确认范围，需由后端幂等和结果核对支持，前端不能仅凭超时再次发送。
- 生成输入、输出和变更步骤以 [PROJECT第04节](../../../PROJECT.md#04-接口与生成代码协作) 为准。使用生成器声明式配置与现成CLI，读取FastAPI自动提供的 `/openapi.json`，直接输出到 `src/api/`；不创建自定义生成脚本文件。初始化时验证FastAPI schema与生成器版本兼容，保留可复现配置与样例。

## 06 Vercel CLI

Vercel CLI 只操作 `frontend` 里的 Next.js 应用。FastAPI 不放进这个项目。仓库还没有 `.vercel/project.json`，因此日常启动、检查和构建仍用 [frontend README](../../../frontend/README.md) 的 npm 脚本。

执行会读取或改变项目的命令前，先在 `frontend` 运行：

```sh
vercel project inspect --non-interactive
```

输出的 owner 和 project 必须与本次目标一致。出现 `link_required`、未登录或项目不符时停止，不自动执行 `vercel link`、`vercel pull` 或部署。`vercel whoami` 只说明账号和团队，不能代替项目核对。登录或团队 SAML 需要用户本人完成。

链接须用户明确给出团队和项目。只部署前端时，在 `frontend` 执行 `vercel link`，让 `frontend/.vercel/project.json` 指向该应用。不要在仓库根目录创建 `project.json`，否则整个仓库会被当成一个项目，Next 应用根目录会错。以后若后端也成为另一个 Vercel 项目，再在仓库根使用 `vercel link --repo`；在那之前不创建 `repo.json`。`.vercel/` 不提交。

环境变量按 production、preview、development 分开。名称用 `vercel env ls` 查看；值不写入文档、日志或命令行历史。令牌放在环境变量 `VERCEL_TOKEN`，不写进 `--token`。`NEXT_PUBLIC_` 和 `frontend/public` 都视为公开内容。`vercel env pull` 只写入已忽略的 `.env.local`。需要注入时使用 `vercel env run -- <命令>`，`--` 不能省。

本地要使用已链接的开发环境时，绑定本机回环，不用 CLI 默认的 `0.0.0.0`：

```sh
vercel dev --listen 127.0.0.1:3000
```

部署从已核对的 `frontend` 目录执行。不带 `--prod` 的 `vercel deploy` 是预览；生产部署、提升和回滚都要单独授权。需要绕过构建缓存时用 `vercel deploy --force`，不要加 `--with-cache`。`vercel redeploy` 不能做无缓存重建。先 `vercel build` 再部署时必须带 `--prebuilt`。部署 URL 只取 stdout。访问受保护的预览用 `vercel curl`，不关闭 Deployment Protection。

非交互命令已由代理环境附加 `--non-interactive`。只有用户已授权且该命令确实要求确认时才加 `--yes`。

## 07 格式与质量门槛

TypeScript strict、ESLint、Prettier 分别负责类型、代码质量和格式；关闭互相冲突的格式规则。不要为了通过检查批量添加 `any` 或 disable。

命令直接调用现成 CLI，不编写额外脚本文件。现有命令以 `frontend/package.json` 和 README 为准；`api:generate` 在正式 HTTP 接入时配置：

| 命令名 | 必须完成的检查 |
|---|---|
| lint | ESLint 检查；使用与选定 Next.js 版本兼容的 CLI |
| format:check | Prettier 只读格式检查 |
| typecheck | TypeScript 无输出类型检查 |
| build | Next.js 生产构建 |
| api:generate | 通过 Umi OpenAPI 现成 CLI 读取后端自动生成的接口定义，输出到 src/api |

对有状态交互、权限与请求适配补充有意义的组件/集成测试；界面交付执行实际浏览器与目标设备检查。格式检查不能替代 API 联调，构建通过不能替代媒体播放或真实开播验收。

提交格式统一引用[AGENTS第05节](../../../AGENTS.md#05-代码提交规范)，使用 `type(scope): xxx`；`style` 仅表示代码格式调整，用户可见的界面能力或缺陷按 `feat` 或 `fix` 分类。
