# 01 后端开发规范

## 01 适用范围与规范来源

适用于 [backend](../../../backend/README.md)。Python 编码遵循 [Google Python Style Guide](https://google.github.io/styleguide/pyguide.html)，Web 结构遵循 [FastAPI 官方指南](https://fastapi.tiangolo.com/tutorial/bigger-applications/)。2026-10-27已再次核对这两份来源。

它们分别约束语言和框架，不是一份名为 Google FastAPI 的独立标准。分层、契约和质量门槛是本项目约定。接口、权限、数据表和供应商选择以正式设计为准。

## 02 分层与目录

| 路径（相对 backend） | 职责 |
|---|---|
| app/api | 按功能使用 APIRouter；处理 HTTP 输入、依赖和响应，不设版本号子目录 |
| app/core | 配置加载、日志、基础异常和通用安全设施 |
| app/schemas | Pydantic 请求/响应模型，与外部供应商结构分离 |
| app/services | 用例与业务规则，通过注入的适配器访问外部能力 |
| app/integrations | 外部 HTTP/媒体服务适配，集中处理供应商协议、超时与错误 |
| app/skills | 运行 Skill 及角色预设；规则来源、适用边界和版本可追溯，不存密钥或生成中间图片 |
| tests | 后端测试；不建立契约导出目录或自定义脚本目录 |

`app/main.py` 负责应用装配、lifespan、中间件、异常处理和 `include_router`；`__init__.py` 在创建可导入包时补齐。依赖方向为 API → services → integrations，schemas/core 提供公共基础。services 不导入路由，不接收 `Request`。不为分层制造空抽象基类。

持久化确认后才增加 models、repositories 和迁移目录。SQLite 账本仍是设计方案，当前没有运行数据库或队列。

## 03 Google Python 编码规则

- 使用 4 个空格缩进，不用 Tab。行宽上限 80；长 URL、导入和无法合理断开的长字符串沿用官方例外。续行放在括号内，不用反斜杠。
- 顶层函数和类之间空两行，类内方法之间空一行。包、模块、函数和变量使用 snake_case，类使用 CapWords，常量使用 UPPER_SNAKE_CASE，异常以 `Error` 结尾。模块文件使用 `.py`，不用连字符。
- 导入按 future、标准库、第三方、本项目分组，组间空一行，组内排序。使用绝对导入，优先导入模块再用模块名访问符号：`from app.schemas import character_assets as schemas`。类型注解所需符号沿用 Google 指南的明确例外。FastAPI 示例里的相对导入在本项目不采用。
- 不在函数内部导入，除非这是消除真实循环依赖的最后手段；应先调整分层。
- 公共函数、依赖、服务和适配器写完整参数与返回类型。可空写成 `X | None`，不用无约束 `Any` 掩盖未知数据。局部变量不强制注解。输入在边界校验，不用 `assert` 承担生产验证，也不用可变对象作默认参数。与 `None` 比较使用 `is`。
- 公共模块、类和函数使用三双引号 docstring。摘要用中文说明行为、约束和副作用，不复述函数名；段名保留英文 `Args`、`Returns`、`Raises`。测试文件不要求 docstring。
- 精确捕获可处理的异常，缩小 `try` 范围；禁止 `except Exception: pass`。宽泛捕获只出现在明确隔离边界，并且要保留错误语义和清理路径。
- 使用 `logging`。带参数日志使用占位符和独立参数，例如 `logger.info("request_id=%s", request_id)`，不用 f-string 预先拼进日志。日志不包含长期密钥、完整凭据和未脱敏正文。

工具不能覆盖全部 Google 条款。Ruff 已启用 pycodestyle、pyflakes、isort、pyupgrade、bugbear 和 pydocstyle 的 Google 约定；D415 只认英文句号，中文摘要因此豁免，其余 docstring 规则保留。人工仍要看导入方式、异常语义和日志内容。

## 04 FastAPI 使用约定

一个功能一个模块、一个 `APIRouter`。路由前缀表达功能，`main.py` 统一加上 `/api`。目录和 URL 都不加版本号。`operation_id` 使用稳定的 camelCase，全应用唯一，例如 `prepareCharacterAssetTask`。`tags`、`summary`、`description` 和 `responses` 写在装饰器上；普通注释不会进入 OpenAPI。

返回注解就是响应契约。只有在需要隐藏字段或与返回值不同的序列化模型时才另设 `response_model`。对外模型继承现有 `StrictModel`：`extra="forbid"`、`frozen=True`，字段用 `Annotated` 和 `Field` 写长度、模式和数量约束。跨字段规则放 `model_validator`。不把供应商对象或 `dict[str, Any]` 直接作为响应。

最小路由保持这层分工：

```python
"""说明本模块的HTTP边界。"""

from fastapi import APIRouter

from app.schemas import feature as schemas
from app.services import feature as service

router = APIRouter(prefix="/feature", tags=["功能名"])


@router.get("/items", operation_id="listFeatureItems", summary="列出条目")
def list_items() -> tuple[schemas.Item, ...]:
    """返回已校验结果，不访问收费服务。"""
    return service.list_items()
```

读取本地 Skill 或做短计算时使用普通 `def`。FastAPI 会把同步路由放进线程池。`async def` 里只调用不阻塞事件循环的异步 I/O；同步文件、阻塞 HTTP 和 `time.sleep` 不放进 `async def`。CPU 密集或长时间媒体工作不占用请求线程，执行模型另经设计确认。

配置、身份和客户端用 `Depends` 与 `Annotated` 注入，不在每个路由里新建连接。必需配置在启动时校验，缺失就失败。共享连接在 lifespan 中创建和释放。导入应用模块不得发起网络连接或收费会话。

Pydantic 校验失败保持 422。服务层用 `ValueError` 或领域异常表达可预期拒绝，不抛 `HTTPException`。API 层把这些拒绝转换成约定状态和错误模型；鉴权、依赖失败和内部故障分开表示，未知内部错误不返回堆栈。当前角色美术路由还没有把服务层 `ValueError` 映射成 4xx，新接口不能沿用这个缺口，也不能把损坏配置返回成成功。

外部调用设置连接和读取超时。重试必须有幂等依据、有限次数和可观测性。结果未知时保持未知，不用无限重试再创建一次生成会话。`BackgroundTasks` 不是持久队列。

CORS 只允许实际来源。当前应用只接受本机 Host 和本机 Origin，不启用通配来源加凭据。生产文档暴露、Cookie、CSRF、回调签名和访问控制按正式安全设计落地。

## 05 OpenAPI 与跨端契约

契约流程见 [PROJECT第04节](../../../PROJECT.md#04-接口与生成代码协作)。模型名避免生成冲突。写明 null 与缺省、枚举、必要时的分页、UTC 时间和错误响应。改变状态的接口不用 GET。

`/openapi.json` 和 `/docs` 使用同一份自动生成的定义。不手写 Swagger 文件，不另做导出脚本。读取 schema 不得触发真实生成、开播或收费会话。OpenAPI 规范版本与 `@umijs/openapi` 的兼容性必须用样例验证，不改规范版本字段伪装兼容。

## 06 工具与验证门槛

运行依赖、开发依赖、Python 版本和工具配置集中在 `pyproject.toml`，锁文件为 `uv.lock`。格式和 lint 用 Ruff，类型用 mypy strict 与 pydantic 插件，测试用 pytest。这是本项目工具组合，不等于 Google 内部使用的 Pylint 或 pytype。

在 backend 目录执行：

```sh
uv run --locked ruff check app tests
uv run --locked ruff format --check app tests
uv run --locked mypy app
uv run --locked pytest -q
```

| 检查 | 完成依据 |
|---|---|
| 格式与 lint | 只读检查通过，抑制项有具体理由 |
| 类型 | 公共边界与主要服务通过 strict，不批量关闭规则 |
| 单元/接口测试 | 业务规则、校验、权限、异常与依赖替换有可核对结果 |
| 契约测试 | schema 可读取、operation_id 唯一、客户端可再生成且类型通过 |
| 集成验收 | 真实依赖、媒体和费用结果单列；Mock 不作为真实开播证据 |

测试不默认调用收费生成或真实开播。已确认业务实现后，按计划覆盖超时、重复命令、迟到事件、恢复和终止未知；追溯到 FR/NFR → DES → US/AC → T → TC。
