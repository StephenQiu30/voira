# 02 文档目录规范

## 01 适用范围

本文规定 Markdown 放在哪。怎么写见[文档编写规范](01-文档编写规范.md)，代码目录见[PROJECT](../../PROJECT.md)，通用视觉见[DESIGN](../../DESIGN.md)。需求、设计、验收、计划和研究文件已经在对应目录，不再搬迁。

## 02 仓库入口

这些文件留在 `voira-server` 根目录，不复制进 `docs`：

| 文件 | 唯一内容 |
|---|---|
| README.md | 对外介绍 |
| AGENTS.md | 执行顺序与提交 |
| PROJECT.md | 工程结构与技术栈 |
| DESIGN.md | 通用视觉 |
| BLACKLOG.md | 任务状态 |
| HANDOVER.md | 当前能力与验证边界 |

`frontend/README.md`、`frontend/AGENTS.md`、`backend/README.md`、`backend/AGENTS.md` 留在对应端，只作短入口，并链接到下面的长规范。不把规范正文再抄一份。

## 03 知识库

在 Obsidian 打开 `docs`。

| 位置 | 放入 | 不放入 |
|---|---|---|
| 00-知识库导航.md | 阅读入口 | 规则正文 |
| requirement | 一功能一需求 | 接口契约、验收步骤全文 |
| design | 现行设计 Markdown | 样式、令牌、图片 |
| prd | 用户故事与可测试 AC | 实施任务 |
| plan | 依赖、任务与测试规格 | 当前进度 |
| research | 会改变方案的结论 | 抓取原文和过程记录 |
| standard | 现行规范 | 空白模板、旧稿和归档 |

同一目录内的文件从 00 或 01 起连续编号。`requirement` 的文件号对应需求文档序号，`design` 为 00—08。稳定的 FR、DES、US、AC、T、TC、RES 不因换目录而改号。

## 04 规范按端放置

| 路径 | 约束对象 |
|---|---|
| standard/01-文档编写规范.md | 知识库怎么写 |
| standard/02-文档目录规范.md | 文档放在哪 |
| standard/frontend/01-前端开发规范.md | Next.js 前端；组件遵循 shadcn，平台命令遵循 Vercel CLI |
| standard/backend/01-后端开发规范.md | FastAPI 后端；Python 遵循 Google 风格，Web 结构遵循 FastAPI |

`frontend` 与 `backend` 是各自的目录，编号都从 01 开始。前端规则不写进 backend，Python 和 FastAPI 规则不写进 frontend。新增同类规范时在该目录续号，不恢复 `templates` 这个名字。

## 05 留在原处的材料

- `backend/app/skills` 是运行规则和角色配置，留在后端包内，不拷进 `docs`。
- `frontend/public` 是页面展示资源。`../public` 是仓库外的本地素材库。
- `../voira-pet/docs` 与 `../voira-pet/articles` 属于宠物仓库。
- `output` 和 `.local` 不进入知识库。

## 06 移动后的检查

移动文件后同步链接、导航和文件标题中的编号。不建 `docs` 归档目录，不把过程记录写成新文档。代码目录变化只改 PROJECT，视觉变化只改 DESIGN。
