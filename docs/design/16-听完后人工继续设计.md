# 16 听完后人工继续设计

设计编号：**DES-030**；唯一主需求：[FR-023 听完后人工继续](../requirement/24-听完后人工继续.md)（业务规则及确认状态以该文档为准）。当前网页PoC；关联共享设计DES-014。本设计是T-024文档交付，尚未实现或执行真实调用。

## 01 设计范围与决策

新增ContinueTurn用例替代参考kick/估时调度。唯一作用是记录用户听完确认、提交当前完整轮次上下文并释放占用，不触发Codex或Vidu。

源码依据：[RES-008](../research/07-参考仓库到网页PoC实现映射.md)中的SRC-07。这些是固定提交的静态证据；本项目改造建议与上游行为分开记录。公共接口、状态枚举与表结构以[共享设计](03-Vidu网页PoC最小业务设计.md)为唯一契约来源，本文定义本功能责任。

## 02 用户流程与状态

sent且控制/媒体健康 → 显示“我已听完，继续提问”与人工判断提示 → 点击 → 服务端在会话锁内核对当前输入 → 记录人工确认 → 更新三轮上下文 → 解锁输入。已有下一问草稿保持原样，需再次点击发送。

结束和继续竞争时以服务端锁与结束意图为准，已ending拒绝首次继续。无回应、发送未知、生成失败或连接异常不能通过按钮跳过。文本完成、静音和计时不触发该接口；误点可能重叠的PoC限制持续提示。

## 03 接口与责任边界

POST /api/sessions/{id}/inputs/{input_id}/continue请求outcome=heard_finished；成功200回原输入回执。首次请求必须是当前sent，其他状态409；已确认的同一输入重复请求只返回旧确认结果，不动后来的活动轮次。输入属于其他会话不能操作。

HTTP接口按共享契约各自遵循同源、本机、控制令牌、幂等与错误规则（只读配置查询不要求会话令牌）；不存在的端点不宣称已可访问。内部适配接口是拟实现边界，不额外创建网络服务或脚本。

## 04 数据与生命周期

inputs.user_confirmed_at与confirmation_source=user持久化，state=continued_by_user；事务中释放inputs.active_slot并增加session revision，快照据占用派生active_input_id=null。内存上下文更新在同会话锁内完成，成功响应前不接收下一轮；崩溃则结束会话并清空正文，不从元数据重造记忆。

如涉及共享表，约束/索引/迁移见共享设计第04节；不为本功能单独复制一套数据库。正文、秘密和恢复元数据分别处理。

## 05 验证与追溯

[最小设计](../design/03-Vidu网页PoC最小业务设计.md)：DES-014；[验收标准](../prd/01-网页数字人PoC产品与验收标准.md)：US-002；AC-008；[验证计划](../plan/07-网页数字人PoC验证计划.md)：TC-017。真实场景均未执行。

本功能重点：双击只追加一次上下文；重复上一轮确认不释放下一轮；草稿不自动发送；结束竞争、无回应及未知都不能误标播完。

跨功能NFR沿用共享设计第05节；静态契约检查、模拟依赖、真实服务与人工评审分开记录。当前TC-016—020全部未执行，详细任务与证据见[计划07](../plan/07-网页数字人PoC验证计划.md#14-参考仓库到逐功能设计)。

## 06 评审出口

确认过的业务选择不重复开放；剩余问题以本功能需求第04节及总索引Q责任路由为准。具体素材/音色、模型隔离与媒体能力仍需验证，账号/测试规模/预算在实际调用前落实。实现须获得后续授权，本轮未写业务代码、迁移或调用脚本。
