# 01 网页体验界面设计

## 01 范围与依据

用户授权先统一前端设计，并明确选定品牌“声伴 · Voira”。品牌名称已确认，页面方案和原创Logo为设计交付，尚未经过用户视觉验收。业务遵循[当前需求](../requirement/01-数字人MVP需求草案.md)：网页优先、直播后置。配色与尺寸唯一来源为[DESIGN](../../DESIGN.md)，工程结构见[PROJECT](../../PROJECT.md)。

[Figma设计文件](https://www.figma.com/design/ZO9RS5jCJqDWBnAxB8yV2w)保留品牌/设计系统、历史分栏、交互状态参考、角色资产与角色舞台五页；当前视觉入口见第14节。界面使用原生可编辑文本、矢量、变量、组件及自动布局；人物为静态AI素材，不是真实媒体。工程目录与GitHub仓库于T-059统一为voira；产品显示名继续为声伴Voira，Figma历史文件名不在本轮更改。

参考[抖音作品](https://www.douyin.com/user/MS4wLjABAAAA4Ifyzc7S7vgKqqsMD1ccen4br6oLao63C8Skl6JRpyk?modal_id=7697175786456911113)及[既有观察V06/V07](../research/03-参考作品观察.md)：取人物居中、控件避免遮挡的原则；不引入直播评论、商品、礼物、拖动面板、换装或独立播出窗口。本轮浏览器再次读取作品文案，作者明确为0.2.8本地演示、未连接实时数字人会话；不把该作品当作实时效果验收。

## 02 品牌与信息结构（DES-001）

正式产品显示名称为**声伴 · Voira**。主字标Voira，中文声伴用于品牌说明与页脚；Logo以两侧声波环抱中央声音表达陪伴。参考口号“有声回应，陪伴在场。”仅用于设计说明，页面不增加营销模块。

本阶段只有一个网页体验页：Header品牌 → Content页面标题、媒体、会话控制 → Footer品牌与AI标识。没有需要切换的业务页面，因此不增加侧栏、账户菜单、仪表盘或空导航。所有设计稿持续标识“设计预览”，实现接真实服务时仍保留“AI 数字人”标识。

品牌资源：[单色Logo](../../frontend/public/brand/voira-mark.svg)、[浅底字标](../../frontend/public/brand/voira-wordmark-light.svg)、[深底字标](../../frontend/public/brand/voira-wordmark-dark.svg)。字标SVG的文字保留为文本，使用者需有字体或沿用系统回退；不是已转曲的商用字体包。未进行商标或域名可用性检索。

## 03 全局布局（DES-002）

BasicLayout只处理品牌、内容容器与页脚。单个页面的MediaPlayer与SessionControls放在内容槽位中，业务状态不得进入全局布局。精确token与断点见DESIGN第09—11节。

1440×960桌面设计中Header为64px，Content示例840px，Footer为56px；最大内容宽1200px，因此实际左右留白120px。Content高度在实现中为弹性值，840不是所有设备固定值。主要工作区为媒体848px、间距32px、控制320px；控制区不覆盖人物。媒体完整保留原始比例，采用contain并允许黑边，不强制拉伸或裁剪9:16/16:9素材。

窄屏将媒体、状态、控制和输入顺序重排。390px稿的内容宽358px，页面自然纵向滚动；不用固定页脚遮挡软键盘或输入。窄屏稿是设计预留，不将手机真实媒体验收升级为本阶段要求。

## 04 基础组件（DES-003）

Figma现有库检索未找到shadcn组件或相关主题变量；本轮建立本地组件，与Radix版shadcn语义对应，不混入Material或Base UI。CLI在空骨架中检测到config=null、components=[]；这不改变PROJECT指定的Next.js/Radix栈。

| 界面对象 | 实现映射与约束 |
|---|---|
| 开始/结束/声音/发送 | Button的default、secondary、ghost及disabled；加载采用Spinner + disabled + data-icon，文案保留 |
| 文字输入 | FieldGroup → Field → FieldLabel、InputGroup/InputGroupTextarea、FieldDescription/FieldError；textarea至少16px；placeholder不代替标签 |
| 会话提示 | Alert、AlertTitle、AlertDescription；失败就地显示，不能仅用瞬时Toast |
| AI/会话标识 | Badge；文字与图标共同表达状态 |
| 无素材/未开始 | Empty组合；不播放预录循环假装实时 |
| 如后续需要弹层 | Radix焦点进入/返回与Title；本轮不为示例添加Dialog或设置功能 |

颜色和字体在组件源码/variants统一处理，页面className仅承担布局。保留focus-visible；不以全局border:0或ring:0消除反馈。不新增组件registry或安装组件；实现前按锁定版本核对现成CLI、具体组件API与图标库。

## 05 页面状态与行为（DES-004）

下表是界面契约草案，不假定供应商已有同名事件。后续完整业务设计须映射到真实后端状态、超时与核对接口。

| 状态 | 展示 | 可操作项与边界 |
|---|---|---|
| 未开始 | 尚未开始体验 | 开始可用；输入、发送和声音不可用；素材缺失时不能开始 |
| 连接中 | 正在连接… | 禁止重复开始；不显示虚构百分比；结束可请求取消/终止，具体协议待设计 |
| 可输入 | 已连接 / 可以开始交流了 | 输入、发送、静音和结束可用；空白输入不能发送 |
| 请求处理中 | 正在准备回应… | 已接受不等于开始播放；发送禁用，保留输入 |
| 播放中 | 数字人正在回应 | 串行处理，保留下一条输入；允许静音与结束 |
| 声音受限 | 画面已连接，声音未开启 | 主动开启声音；不因无声播放宣称完整体验成功 |
| 连接失败 | 连接未成功 | 核对旧会话状态；确认无残留后才允许重试 |
| 输入错误 | 请检查输入内容 | 就地关联错误，保留原文；长度上限来自已确认配置，不在设计中编造 |
| 结束中 | 正在结束… | 停止新输入与生成；等待服务端终止确认 |
| 已结束 | 本次体验已结束 | 仅收到终止依据后展示；可再次体验 |
| 终止未知 | 暂未确认会话已结束 | 禁止新建；提供“核对结束状态”；静音不代表停费 |
| 结果未知 | 暂未确认回应结果 | 不自动重发；显示核对入口；未确认不显示完成 |

默认文案按Q-004建议的文字问答设计；若选择指定播读，只替换动作与说明文案，不新增双模式切换器。时间、角色名、字符上限、费用均依真实配置，不伪造实时统计。

## 06 键盘、反馈与响应式（DES-005）

- 焦点顺序：跳至主内容 → 开始/结束 → 声音控制 → 文字输入 → 发送；以实际DOM顺序整理，不使用正tabindex。
- 输入默认Enter换行，Ctrl/Cmd+Enter可作为发送快捷键；必须检查输入法isComposing，中文选字不能误发。按钮始终可点击发送。
- 开始、发送、结束结果通过适度aria-live通知；错误与字段通过aria-describedby关联，aria-invalid/data-invalid配合使用。
- 所有按钮最小44px高；小图标按钮提供可访问名称。浏览器缩放不能禁用，长错误和输入允许换行。
- 动效只用于必要过渡，建议120–180ms；尊重prefers-reduced-motion，不添加循环装饰动画。
- Header/Footer采用自然文档流；缩放、软键盘、长内容下不遮挡焦点。

## 10 点击原型边界（DES-007）

Figma用原生画板跳转表达开始→可输入→回应→结束；快捷话题进入示例回应，手机在手机画板之间跳转。使用即时切换，避免装饰性循环。文字输入、声音开关为状态示意，不接真实输入、语音或数字人；终止未知保留禁止重开的说明。本轮不定义Mock运行控制器、HTTP API或实现测试；后续开发需另行展开。


## 11 沉浸式首页（DES-008）

用户提供暖色人物场景与半透明悬浮面板参考，当前首页采用[DESIGN第14节](../../DESIGN.md#14-沉浸式人物场景修订2026-10-25)。人物居中，面板避开面部与身体主体；桌面左侧介绍/话题、右侧当前交流/输入、底部开始结束与声音控制。手机收敛为单列下部面板。继续使用声伴Voira与原创小伴，不复制参考图中的第三方品牌、商品和活动功能。

未开始、可输入、回应中、已结束/未知终止沿用DES-004的状态规则。原型只模拟选择话题/发送示例与状态跳转，不接受自由输入、播放音频或调用真实服务。旧分栏稿保留比较，新首页以沉浸式画板为准。

历史入口（T-065已清理，当前入口见14.11节）：[沉浸式桌面](https://www.figma.com/design/ZO9RS5jCJqDWBnAxB8yV2w?node-id=17-14)、[沉浸式手机](https://www.figma.com/design/ZO9RS5jCJqDWBnAxB8yV2w?node-id=18-82)。共12张新稿，包含两端未开始、可输入、已结束及三个预设回应。未知终止等完整状态规范继续保留在历史状态板，未宣称本轮12张稿覆盖全部业务状态。

人物场景素材为本轮imagegen编辑模式生成：以既有原创小伴为身份参考、用户截图为室内构图参考，生成宽幅暖色客厅、居中坐于浅色沙发的成年女性，保留自然面容、米白服装与两侧安静背景；不含界面、文字或第三方标识。素材为静态视觉提案，UI由Figma原生文字、矢量与组件叠加。


## 12 五位角色与交互细化（DES-009）

用户确认角色顺序：蓝色大肥鱼、Gemini、Claude、Grok、ChatGPT，共五位。截图中的第四位金发黑红礼服对应Grok，不另增第六位。素材生成方式、提示词与public路径见[生成记录](02-五位角色素材生成记录.md)，视觉规则见[DESIGN第15节](../../DESIGN.md#15-五位角色与手机交互细化2026-10-25)。角色为AI静态插画与独立透明图层，UI继续使用Figma原生文字/矢量/组件。默认首页以第一位展示，其余四位在角色资产板评审，不引入真实模型路由或新的业务角色选择器。

本轮将沉浸式状态补到两端：连接中、请求处理中、声音受限、连接失败、输入错误、结束中、终止未知、结果未知及已静音。开始先展示连接、发送先展示处理、结束先展示终止确认；忙时与未知结果禁止提交，未开始/已结束的快捷话题禁用。Figma延时仅为演示节奏，不对应真实时延承诺。

手机增加收起/展开交流与输入聚焦两张稿：首屏收起话题和输入，完整展示人物；交流展开保留面部；输入聚焦缩短场景，将输入与结束入口置于系统键盘示意区上方。键盘为静态占位，未模拟系统真实键盘。人物/场景分别缩放；不以固定画板几何证明所有视口已适配。
