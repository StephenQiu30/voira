# 05 开始网页会话设计

设计编号：**DES-019**；唯一主需求：[FR-002 开始网页会话](../requirement/03-开始网页会话.md)（业务规则及确认状态以该文档为准）。当前网页PoC；关联共享设计DES-013/016/017。本设计是T-024文档交付，尚未实现或执行真实调用。

## 01 设计范围与决策

SessionService独占一个未结清会话槽。沿用参考的REST创建、WS初始化、RTC入会分层；新增持久化创建意图与未知状态，禁止自动重开。

源码依据：[RES-008](../research/07-参考仓库到网页PoC实现映射.md)中的SRC-02/03/09。这些是固定提交的静态证据；本项目改造建议与上游行为分开记录。公共接口、状态枚举与表结构以[共享设计](03-Vidu网页PoC最小业务设计.md)为唯一契约来源，本文定义本功能责任。

## 02 用户流程与状态

打开页面只查配置 → 用户开始 → 校验配置/批准额度 → 本地事务占槽并预留用量 → 创建Vidu会话 → 保存live_id → WS ready → 网页加入RTC并报告首帧。仅控制与首帧都就绪才到active；声音可播放状态单列。

明确未发出/供应商明确拒绝才failed_no_session。请求可能发出但无确定结果为creation_unknown，保留槽并核对，不能重新POST上游。客户端请求取消不撤销后台意图；创建中用户结束则记停止意图，外部ID一到立即清理。

## 03 接口与责任边界

归属POST /api/sessions、GET /api/sessions/{id}及POST /api/sessions/{id}/connection，字段/状态码以共享设计03第03节为准。创建键及控制令牌在首次请求前保存在当前标签页；重发同意图沿用两者。202表示本地受理；重复键不同参数409，未结清槽409，缺配置/额度409。

HTTP接口按共享契约各自遵循同源、本机、控制令牌、幂等与错误规则（只读配置查询不要求会话令牌）；不存在的端点不宣称已可访问。内部适配接口是拟实现边界，不额外创建网络服务或脚本。

## 04 数据与生命周期

sessions持久化create_key、controller_token_hash、config_version、run_id、active_slot、state、provider_live_id、revision及时间。先落意图再出网；成功取得外部ID立即保存。RTC凭据仅内存与短期响应，不写普通日志。

如涉及共享表，约束/索引/迁移见共享设计第04节；不为本功能单独复制一套数据库。正文、秘密和恢复元数据分别处理。

## 05 验证与追溯

[最小设计](../design/03-Vidu网页PoC最小业务设计.md)：DES-013；[验收标准](../prd/01-网页数字人PoC产品与验收标准.md)：US-001；AC-002/003/004；[验证计划](../plan/07-网页数字人PoC验证计划.md)：TC-016。真实场景均未执行。

本功能重点：双击、响应丢失、创建返回前结束、创建后后端崩溃都最多一次创建意图；页面/Swagger/刷新不得产生收费会话。

跨功能NFR沿用共享设计第05节；静态契约检查、模拟依赖、真实服务与人工评审分开记录。当前TC-016—020全部未执行，详细任务与证据见[计划07](../plan/07-网页数字人PoC验证计划.md#14-参考仓库到逐功能设计)。

## 06 评审出口

确认过的业务选择不重复开放；剩余问题以本功能需求第04节及总索引Q责任路由为准。具体素材/音色、模型隔离与媒体能力仍需验证，账号/测试规模/预算在实际调用前落实。实现须获得后续授权，本轮未写业务代码、迁移或调用脚本。
